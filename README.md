# TAA Satellite — 8자산 이동평균 히스테리시스 시그널 봇

코어 전략(QQQ / TLT / GLD)과 **별개로** 운용하는 위성 포트폴리오용 일일 시그널 봇입니다.
매 거래일 종가 기준으로 목표 비중을 산출해 텔레그램으로 전송합니다.

시그널 규칙(밴드·스케일링·집행 시점)은 코어 TAA와 **완전히 동일**하며,
자산 유니버스와 기준비중만 다릅니다.

---

|---|---|---|

> 총합 상한은 두지 않습니다 — 자세한 내용은 아래 4절 참고.

## 2. 시그널 규칙

### 2-1. 히스테리시스 밴드 (코어 TAA와 동일)

이동평균 **20 / 120 / 200일** 각각에 대해 ON/OFF 상태를 판정합니다.

| 현재 상태 | 전환 조건 |
|---|---|
| OFF → ON | 종가 > MA × (1 + **1.5%**) |
| ON → OFF | 종가 < MA × (1 − **2.5%**) |
| 밴드 사이 | 직전 상태 유지 (거래 없음) |

단순 MA 교차 대비 밴드 사이의 휩쏘(whipsaw)를 억제하는 것이 목적입니다.
매수 진입 문턱(+1.5%)이 매도 이탈 문턱(−2.5%)보다 낮은 **비대칭 구조**로,
추세 진입은 빠르게, 이탈은 관대하게 처리합니다.

### 2-2. 점수 → 비중

| 점수 (ON 개수) | 스칼라 | 목표 비중 |
|---|---|---|
| 3 / 3 | 100% | **20%** |
| 2 / 3 | 75% | **15%** |
| 1 / 3 | 50% | **10%** |
| 0 / 3 | 0% | **0%** |

미배분 잔여분은 전량 현금입니다.

### 2-3. 집행 시점 (lag = 1)

시그널은 **당일 종가**로 계산하고 **다음 거래일에 집행**합니다.
당일 종가로 계산한 신호를 당일 종가에 체결한다고 가정하면 룩어헤드 편향이 발생하며,
이는 백테스트 성과를 실제보다 과대평가하게 만듭니다. 리포트 상단에도 항상 명시됩니다.

## 3. 상태 관리 — stateless 설계

히스테리시스는 경로 의존적이지만, 이 봇은 상태 파일을 저장하지 않습니다.
매 실행마다 **전체 히스토리**(`LOOKBACK = "max"`)로 밴드 상태를 처음부터 재현하므로,
러너가 초기화되거나 실행이 며칠 누락되어도 결과가 동일하게 재현됩니다.

짧은 기간만 받으면 상태가 0에서 출발해 실제와 다른 신호가 나오고,
매일 시작점이 밀려 어제와 오늘 결과가 뒤집힙니다. `LOOKBACK` 은 줄이지 마세요.

최소 요구 길이는 `max(MA) + WARMUP_EXTRA = 450 거래일`(약 1.8년)입니다.
이보다 상장 이력이 짧은 종목은 비중 0%로 두고 **처리 실패** 항목에 표시되며,
실행이 중단되지는 않습니다. 신규 상장 ETF를 빨리 넣고 싶다면 `WARMUP_EXTRA` 를
낮출 수 있지만, 초기 신호의 신뢰도는 그만큼 떨어집니다.

---

## 4. 비중 상한 — 자산별 20%만 적용

각 자산의 비중은 **오직 자기 점수로만** 결정됩니다. 다른 자산이 몇 개 ON인지와 무관하며,
유니버스에 종목을 추가해도 규칙은 그대로입니다 (자산별 최대 20%).
총합 상한은 두지 않습니다 — `BASE_WEIGHT` 하나가 자산별 상한이자 기본 비중입니다.

```python
BASE_WEIGHT = 0.20   # 자산별 상한(=기본 비중). 총합 상한 없음
```

다만 8자산 × 20% = 160%이므로, 많은 자산이 동시에 ON인 국면에서는
합계가 100%를 넘을 수 있습니다. 이 경우 리포트가 초과분을 경고하고
**100% 기준 환산 비중**을 함께 표시하므로, 실제 집행 시 참고하면 됩니다.

```
　　 0%  현금
　　 위험자산 합계 120%

⚠️ 합계가 100%를 20%p 초과
100% 기준 환산 비중
· 한국 주식  12.5%  ·  ₩6,250,000
· 중국 주식  12.5%  ·  ₩6,250,000
  ...
```

나중에 총합 상한(예: 일반 계좌 100%, 연금저축·IRP 위험자산 70% 제한)을 강제하고 싶다면
비중 산출 뒤 전 자산을 비례 축소하는 단계를 추가하면 됩니다. 현재는 판단을 코드에 맡기지 않고
초과 사실만 알려주는 방식입니다.

## 5. 설치 및 운영

### 5-1. 로컬 실행

```bash
pip install -r requirements.txt
python satellite_signal.py          # 환경변수 없으면 콘솔 출력만
```

| 환경변수 | 필수 | 설명 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | O | 봇 토큰 (구 `TELEGRAM_TOKEN` 도 인식) |
| `TELEGRAM_CHAT_ID` | O | 수신 chat_id (구 `TELEGRAM_TO` 도 인식) |
| `PORTFOLIO_VALUE` | X | 평가액(KRW). 넣으면 목표 수량(주)까지 계산 |
| `ALWAYS_SEND` | X | `false` 면 비중 변동이 있을 때만 전송. 기본 `true` |

```bash
export TELEGRAM_BOT_TOKEN="123456:ABC-..."
export TELEGRAM_CHAT_ID="123456789"
export PORTFOLIO_VALUE="50000000"
python satellite_signal.py
```

### 5-2. GitHub Actions

1. 저장소 → **Settings → Secrets and variables → Actions**
   - Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`
   - Variables(선택): `PORTFOLIO_VALUE`, `ALWAYS_SEND`
2. `.github/workflows/signal.yml` — 평일 18:00 KST(09:00 UTC) 자동 실행
3. `.github/workflows/keepalive.yml` — 매월 1일/15일, schedule 자동 비활성화 방지

> **cron 정확도**: GitHub Actions 의 schedule 은 부하에 따라 수 분~수십 분 지연될 수 있습니다.
> 신호를 놓치지 않으려면 여유 있는 시각(18:00 KST)에 두는 편이 안전하며,
> 필요 시 `workflow_dispatch` 로 수동 실행할 수 있습니다.

### 5-3. 파일 구성

```
taa_satellite/
├── satellite_signal.py            # 시그널 산출 + 텔레그램 전송
├── requirements.txt
├── README.md
└── .github/workflows/
    ├── signal.yml                 # 평일 일일 실행
    └── keepalive.yml              # schedule 유지용
```

## 5-4. 텔레그램 리포트 형식

코어 TAA 봇과 동일한 HTML 포맷을 사용합니다.

```
🛰 TAA Satellite — 국내 8자산
2026-08-14 KST
기준: 2026-08-13 마감 · 익일 집행

■ 리밸런싱 필요 — 2건
🔴 일본 주식  10% → 15%  (120일↑)
🔵 현금  40% → 35%

■ 목표 비중
● = 20/120/200일선 ON · 자산별 상한 20%
●●○ 15%  일본 주식  241180.KS
     ₩16,762 ▲0.9%  ·  447주
     20일 +3.8%  120일 +1.7%  200일 -0.4%
　　 35%  현금  ·  ₩17,500,000
　　 위험자산 합계 65%
```

- `●●○` 는 20 / 120 / 200일선 순서의 ON/OFF
- 🔴 = 비중 증가, 🔵 = 비중 감소
- 세 번째 줄은 각 이동평균 대비 이격도
- `PORTFOLIO_VALUE` 설정 시 목표 수량(주)과 현금 금액이 함께 표시
- 4096자 제한을 넘으면 자동 분할 전송

## 6. 알아둘 점

- **데이터 부족 자산 처리**: 상장 이력이 450 거래일에 못 미치는 종목은 비중 0%로 두고
  리포트의 **⚠️ 처리 실패** 항목에 표시합니다. 실행이 중단되지는 않습니다.
  `0019K0.KS` 같은 비표준 코드는 yfinance 에서 조회되지 않을 수 있으니 첫 실행 로그를 확인하세요.
- **코어와의 팩터 중복**: 계좌는 분리해 독립 운용하지만, `426030.KS`(나스닥 주식)는
  코어의 QQQ와, `385560.KS`(채권 30년)는 코어의 TLT와 사실상 같은 리스크 팩터입니다.
  두 계좌 합산 기준으로는 나스닥·미국 장기채 익스포저가 의도보다 커집니다.
- **국내 상장 ETF 특성**: 해외지수 추종 ETF는 기초자산과 거래 시간대가 어긋나
  괴리율과 갭이 발생합니다. 합성(스왑) ETF는 추적오차·보수도 함께 확인하세요.
- **아직 검증되지 않은 유니버스**: 이 저장소는 **시그널 산출 봇**이며,
  코어 TAA처럼 룩어헤드 진단 · 워크포워드 OOS · 그리드서치 DSR · 블록 부트스트랩까지
  거친 결과가 아닙니다. 실계좌 투입 전 동일한 검증 절차를 권장합니다.
- **투자 판단 책임**: 이 코드는 참고용 도구이며 투자 권유가 아닙니다.
